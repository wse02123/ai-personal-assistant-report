룰과 AI의 역할 분담

정해진 프로세스는 n8n 룰이 강제하고, 대화의 변수만 AI가 판정합니다.

n8n

정해진 프로세스의 강제

의도가 정해지면 카테고리 읽기 → 내용 분석 → 시트 저장 → 캘린더 등록까지 정해진 순서로만 진행합니다. 버튼 응답과 명시 명령은 AI 판정을 거치지 않고 룰이 즉시 처리합니다.

02

시간 없이 날짜만 있으면 종일 이벤트로 등록합니다.

03

날짜 범위

시작일과 종료일이 다르면 범위 전체를 하나의 이벤트로 등록합니다.

한 메시지에 일정이 여러 건이면 쪼개서 등록합니다 "테니스 일정 등록해" 뒤에 날짜별 코트가 여러 줄 나열되면, 공통 정보를 각 줄에 붙여 건별로 분해한 뒤 각각 등록합니다.

판정 품질을 올린 방법

처음엔 끝말 키워드 룰로 의도를 판별했습니다. 룰을 늘릴수록 서로 충돌해서, 목록이 아니라 판정 방식을 바꿨습니다.

오분류를 먼저 모았다

실제로 보낸 문장잘못된 판정원인
내일 3시 은비랑 저녁 약속 잡아줘조회로 오판어미 '~줘'가 조회 룰에 걸림
메가커피 기프티콘 썼어저장으로 오판'썼어'가 완료 키워드 목록에 없음
저번주에 넣어둔 거 뭐였지저장으로 오판어떤 룰에도 걸리지 않아 기본값으로 떨어짐

키워드 목록을 의미 정의로 바꿨다

정의 "어미로 판정하지 말고 행동의 대상으로 판정하라"를 원칙으로 명시했습니다. 새 정보가 있으면 저장, 이미 저장된 무언가를 전제하면 조회·수정·삭제·완료입니다.
예시 헷갈리는 경계마다 정답 예시를 붙였습니다. "수세미 사야해"는 저장, "수세미 샀어"는 완료, "살 거 뭐였지"는 조회처럼 한 단어 차이를 구분선으로 삼았습니다.
검증 모든 판정을 로그로 남겨 무엇이 왜 그렇게 판정됐는지 되짚습니다. 오분류 사례는 그대로 테스트셋이 되어, 판정 로직을 바꿀 때마다 배포 전에 다시 통과시킵니다.

오라클 클라우드 인프라 & mTLS 단말 보안

n8n은 Oracle Cloud Always Free VM에서 24시간 상시 가동됩니다. n8n 관리 화면은 mTLS로 잠겨 있어 클라이언트 인증서가 설치된 단말에서만 접근 가능합니다. Telegram 봇 통신과 외부 API 아웃바운드는 mTLS 영향 없이 정상 동작합니다.
